# گاهنامه با لینک PDF در Google Drive

این راهنما جایگزین راهنمای آپلود PDF نسخه‌های قبلی است. patch تکمیلی روی نسخه tRPC فعلی، همراه اصلاحیه SlowDown/retry آماده شده است.

## رفتار جدید

- ادمین عنوان، توضیحات، تصویر جلد و **لینک فایل Google Drive** را ثبت می‌کند.
- ورودی فایل PDF، آپلود/اعتبارسنجی باینری PDF در لیارا و محدودیت ۱۵۰ مگابایتی PDF حذف شده‌اند. حجم PDF دیگر روی سرور سایت اثری ندارد؛ محدودیت‌های خود Google Drive همچنان اعمال می‌شوند.
- ایجاد، ویرایش، حذف، فهرست و دریافت لینک دانلود همچنان با روتر `journal` در tRPC انجام می‌شوند.
- `getDownloadUrl` لینک Google Drive را به نشانی درخواست دانلود تبدیل می‌کند. سرور سایت PDF را دریافت یا پراکسی نمی‌کند و برای PDF هیچ درخواست S3 نمی‌فرستد.
- **تصویر جلد همچنان با همان روش فعلی تصاویر در لیارا نگه‌داری می‌شود.** نوار پیشرفت فقط مربوط به جلد است. تنظیم CORS موجود برای جلد باقی می‌ماند؛ برای PDF هیچ تنظیم CORS یا API key گوگل لازم نیست.
- لینک‌ها روی مرورگر و سرور از نظر قالب بررسی می‌شوند. تنها فایل روی `https://drive.google.com` پذیرفته می‌شود؛ لینک پوشه، دامنه‌های مشابه جعلی و آدرس دلخواه پذیرفته نمی‌شوند. این اعتبارسنجی، عمومی بودن فایل یا PDF بودن محتوای واقعی آن را اثبات نمی‌کند؛ ادمین باید لینک PDF درست را قرار دهد.

## نصب

در ریشه پروژه:

```bash
git apply --check azarpouyan-journals-google-drive.patch
git apply azarpouyan-journals-google-drive.patch
npx prisma generate
npx prisma migrate deploy
npm run build
```

این بار migration لازم است. روی دیتابیس درست اجرا کنید و پیش از در دسترس قرار گرفتن نسخه جدید آن را اعمال کنید. در localhost، فرایند قبلی `npm run dev` را متوقف و دوباره اجرا کنید. در production با روال فعلی deploy کنید. وابستگی جدید لازم نیست.

migration فقط `pdfUrl` را اضافه و دو ستون قدیمی `pdfKey` و `pdfSize` را nullable می‌کند؛ جدول، رکوردها و فایل‌های قبلی حذف نمی‌شوند. رکوردهای قدیمی فاقد `pdfUrl` در پنل باقی می‌مانند اما تا ثبت لینک Google Drive در فهرست عمومی نمایش داده نمی‌شوند. هر کدام را ویرایش کنید، لینک واقعی همان شماره را وارد و ذخیره کنید. لینک نمونه به‌صورت خودکار به رکوردهای قبلی اختصاص داده نمی‌شود.

PDFهای قدیمی یا ناقص در لیارا خودکار پاک نمی‌شوند. بعد از اطمینان از انتقال، اگر خواستید آن‌ها را دستی پاک کنید. حذف گاهنامه در سایت، فایل Google Drive را حذف نمی‌کند؛ مدیریت آن فایل در حساب گوگل خودتان انجام می‌شود. جلد گاهنامه هنگام حذف/جایگزینی طبق رفتار قبلی پاک می‌شود.

## تنظیم Google Drive و اولین شماره

در Google Drive فایل را باز کنید:

1. Share → General access → **Anyone with the link**.
2. نقش **Viewer** را انتخاب کنید و دانلود برای بینندگان را مجاز نگه دارید.
3. لینک را کپی و در فیلد «لینک فایل PDF در Google Drive» وارد کنید.
4. دانلود را در پنجره ناشناس مرورگر امتحان کنید تا به ورود حساب مالک متکی نباشد.

لینک ارائه‌شده شما برای ثبت در فرم:

```text
https://drive.google.com/file/d/1KpNDUBwlXMd6WrGgF4GS7MYo04jHceER/view?usp=sharing
```

خروجی دکمه دانلود برای آن:

```text
https://drive.google.com/uc?export=download&id=1KpNDUBwlXMd6WrGgF4GS7MYo04jHceER
```

اگر لینک دارای `resourcekey` باشد، در تبدیل حفظ می‌شود. برای لینک‌های `/file/d/.../view`، `/open?id=...` و `/uc?id=...` پشتیبانی وجود دارد.

فایل بزرگ ممکن است صفحه تأیید دانلود/بررسی امنیتی گوگل را نشان دهد. دانلود بدون صفحه واسط، دسترس‌پذیری فایل و محدودیت دانلود گوگل در کنترل سایت نیستند. برای رفع این محدودیت‌ها نه فایل را از سرور سایت عبور می‌دهیم و نه تلاش می‌کنیم تأییدهای گوگل را دور بزنیم.

دسترسی واقعی لینک ارائه‌شده در این محیط تأیید نشد؛ لینک را در حالت ناشناس آزمایش کنید. تنظیم اشتراک‌گذاری حساب شما تغییر داده نشده است.

## بررسی

TypeScript، ESLint، تولید Prisma Client و build production بررسی شدند. آزمون محلی tRPC با دیتابیس/S3 شبیه‌سازی‌شده شامل ساخت و ویرایش با لینک، رد دامنه نامعتبر، حفظ resourcekey، تبدیل لینک واقعی ارائه‌شده، کنترل دسترسی پیش‌نویس، تعارض ویرایش و تأیید آپلود فقط جلد بود. migration روی دیتابیس واقعی شما و دانلود از Google Drive شما اجرا نشده است.
